# 2026-11-09 — Security and code review (0.2.0–0.2.6)

> Permanent record. Written when the review closed; not rewritten. A single-reviewer read, not a red/blue exercise: later audits may revisit these findings — see [the index](./README.md).

**Scope:** what shipped after the 2026-11-04 audit: Play in frotzplay (`@frotzinc/player` 0.2.1 on `@frotzinc/zmachine` 0.1.1) and its HTML and folder exports; the family header, About menu and changelog dialog (`@frotzinc/nuxt-base` 0.3.2); the email report function (`netlify/functions/report.mjs`), the app's first server-side code; the move to frotzsmith.frotzinc.com and the old domain's retiring service worker. Also the deployment headers, CI, and the dependency tree. The `.frotzsmith` package reader, the Skein and extensions were not re-audited (2026-11-04 covered them).

**Method:** reading the app's code and the installed `@frotzinc` packages (the player's export code from its source map); searches for HTML, eval, navigation and message sinks; `yarn audit`; `curl` of the live response headers on the staging and production hosts; and two posts to the live report function with a body that is not JSON (answered 400; nothing is sent for such a body).

**Overall posture: strong.** No High finding. The app's own code has no `v-html`/`innerHTML` (the changelog dialog in `@frotzinc/nuxt-base` uses `v-html` on text it escapes first, from a file fixed at build time). frotzplay's interpreter decodes and runs one instruction at a time, with no generated code, which is a smaller risk than the JIT interpreters it replaces as the default. Tests (1,614 passing) and typecheck were green before and after the fixes.

## Findings and mitigations

| # | Severity | Finding | Mitigation (0.2.7) |
|---|----------|---------|--------------------|
| R1 | **Medium** | **The report function could be scripted.** `elapsed` (the "typed too fast" check) and the hidden `website` field are sent by the client; the per-address count lived in one function instance's memory, so it reset on a cold start and was not shared between instances; and the function parsed any body, whatever its `Origin` or `Content-Type` (confirmed live with a cross-site `text/plain` post). The recipient is fixed by an environment variable, so this was never an open relay: the harm is a flooded inbox and a spent Resend quota. | `netlify/lib/report-guard.mjs` in front of the handler: the `Origin` must name the request's own host; the body must be `application/json`; at most 100 reports are sent a day (Netlify Blobs; each report takes a place before it is sent and counts the places taken, so posts sent together can't share one count; if the store can't be reached, the report still goes). The function's `config.rateLimit` has Netlify refuse more than 5 posts a minute per address at the edge. `tools/report-guard.test.ts`. |
| R2 | **Medium** | **The security notes described a different app.** `docs/06-security.md` said there was no backend and no remote surface, and described Parchment as the Play tab's player; the README's Security paragraph said the same. | `docs/06-security.md`: the report function is in the threat model and has its own section (§10: what leaves the browser, the secret, the limits); frotzplay is described in §3–§5. README and `docs/beta-testing.md` updated. |
| R3 | Low | **Line breaks in a report's title reached the email subject.** Only the browser's code made the title one line. (Sent through Resend's JSON API, so not a header injection in itself.) | The guard collapses whitespace in the title. |
| R4 | Low | **CI checked a ZILF bundle the app does not load.** `ci.yml` tested for `zilf/r5262550/…` while the app loads `zilf/r5262550-w2/…`; the superseded 11 MB bundle was still committed and deployed. | CI reads the bundle's name from `frotzsmith.config.ts` and requires exactly one bundle in the output; `public/zilf/r5262550/` is removed. |
| R5 | Low | **`robots.txt` and `sitemap.xml` named `frotzsmith.netlify.app`**, and the sitemap listed only `/`. | Both name frotzsmith.frotzinc.com; the sitemap lists `/`, `/zil/` and `/technical/`. |
| R6 | Low | **`yarn audit`: 165 advisories** (3 critical, 89 high), all in build and test tooling. The criticals were in vitest 2.1.9 and its `tinypool` (reachable only with the Vitest UI/API server running). `prosemirror-view` (an XSS advisory, a dependency of `@nuxt/ui`) is not in the built site. | vitest and `@vitest/coverage-v8` 3.2.6 (the vitest advisory's fix); in-range transitive packages re-resolved in `yarn.lock`. 17 advisories remain, none in code that is served: 2 critical in `tinypool` 1.1.1, vitest 3's worker pool (a prototype-pollution gadget: it needs an attacker already able to pollute prototypes inside the test process); 2 high (`basic-ftp` under `@axe-core/cli`, `compression` under `serve`); the rest moderate or low under the build and test tools. |
| R7 | Low | **Headers.** The custom domain's HSTS was `max-age` only (Netlify's default there), and there was no `Cross-Origin-Opener-Policy`. | `netlify.toml` sets `Strict-Transport-Security: max-age=31536000; includeSubDomains` (no `preload`) and `Cross-Origin-Opener-Policy: same-origin`; `tools/netlify-headers.test.ts` pins both. |
| R8 | Low | **A share link could load up to 4,000,000 characters of source**, about the whole of the browser's storage for the site, so the autosave after it would fail (with the storage-full notice). | `SHARE_SOURCE_MAX_CHARS` is 1,000,000. |

Also corrected: the compile-timeout message still pointed at the toolbar's bug icon, removed in 0.2.5 (now *About → Report a problem*).

## Residual

- **The CSP still allows `'unsafe-inline'` and `'unsafe-eval'`** site-wide (documented in `docs/06-security.md` §9): Parchment's ZVM and the replay worker's ifvms are JITs, the replay worker evals `glkapi.js`, and both ZILF loaders import `dotnet.js` through `new Function`. With frotzplay the default player, moving headless replay to `@frotzinc/zmachine` and retiring Parchment would remove the JITs; ZILF's loader would need a plain dynamic import.
- **Parchment's frame and the replay worker still share the IDE's origin** (the 2026-11-04 residual, unchanged).
- **The report function's handler is `@frotzinc/nuxt-base`'s**, shared by the other frotz, Inc. sites; the guard added here protects frotzsmith only. The same checks belong in the package.
- **`tinypool` (test runner only)** is fixed by vitest 4, which drops it. vitest 4.1.12 was tried and passed locally, but on CI's runners the ZILF golden tests ran at about half speed under it and timed out (twice; not reproduced locally, with or without `CI` set), so the suite stays on 3.2.6 until that is understood.
- **The daily cap fails open** when Netlify Blobs can't be read, by choice: a storage fault should not stop a real report.
